## Change brief

An admin can configure a provider connection (M7.1–M7.4) and select it for a
campaign (M7.7), but the first evidence that the configuration works is a
player's DM turn failing at the table. Issue #23 is the operator-facing answer
to "will my local model actually work here?" — asked on demand, before a session
depends on it.

The honest version of that question is not "did the HTTP call succeed". A local
endpoint can be reachable, authenticated, and serving the configured model while
still being unable to produce the structured output the DM contract requires
(M6.3/M6.6) — and that is the failure a table would hit. So the test runs one
real minimal call through the *same* adapter path a turn uses and reports five
independently falsifiable fields, rather than one blob verdict.

Every press spends money or compute, so it is rate-limited per connection and
fires only on an explicit admin press: no page-load hook, no save-time hook.

## Specification

AC-1  `POST /api/admin/providers/:id/test` returns `reachable`, `authenticated`,
      `modelExists`, `structuredOutput`, and `latencyMs` — all five present on
      every outcome, success or failure (FR-805).
AC-2  A key the endpoint rejects (401/403) yields `authenticated: false` with
      `reachable: true`; the other fields do not claim more than was learned.
AC-3  An endpoint that does not serve the configured `model_id` (404, or a
      model-not-found error body) yields `modelExists: false` with
      `authenticated: true`.
AC-4  An endpoint that answers prose with no parseable ` ```dm-json ` block
      yields `structuredOutput: false` with `reachable`, `authenticated`, and
      `modelExists` all true.
AC-5  An endpoint that does not answer (connection refused, DNS failure,
      timeout) yields `reachable: false`, and no field claims anything past it.
AC-6  The (N+1)th test of one connection inside the window returns 429 and makes
      **no** provider call; a different connection in the same window is
      unaffected (NFR-301).
AC-7  A disabled connection is testable — an admin must be able to test a draft
      before enabling it.
AC-8  The result is stored on the connection row and returned by
      `GET /api/admin/providers` and `GET /api/admin/providers/:id`, so M7.6 can
      render "last tested" without issuing a test.
AC-9  No response body of any provider endpoint, on any status code, and no log
      line this change writes, contains API key material; `apiKeyLast4` is the
      most that appears (NFR-305).
AC-10 A non-admin receives 403 on the test route and no provider call is made
      (NFR-301).
AC-11 No provider call is issued by any path other than that explicit POST — not
      on list, not on get, not on create or update.
AC-12 `pnpm test` green against live Postgres, `pnpm db:check` reports no drift,
      and `pnpm typecheck` / `pnpm lint` / `pnpm format` are green.

## Decisions

- **The last result is one `jsonb` column on `provider_connections`, not a
  sibling table.** Issue #23 allows either. Nothing in M7.5 or M7.6 asks for
  test *history* — the list column shows the latest result — and a table would
  add a join and a retention question to answer a need nobody has stated. The
  timestamp lives inside the stored object rather than in a second column, so
  there is one source of truth for "when was this tested".

- **The test builds its provider through the same row→provider path a DM turn
  uses.** `DmProviderSource.get` (M7.7) already validates the URL, decrypts the
  key, and calls `buildDmProvider`; that sequence is extracted to
  `ProviderConnectionsService.sourceFromRow` and both callers use it. A test that
  built its own client would be testing a second code path, which is precisely
  the reassurance it must not give.

- **Rate limit: 5 tests per minute per connection, in-process.** The existing
  `TokenBucket` (`session/token-bucket.ts`, M2.5) is the mechanism; the state is
  a `Map` keyed by connection id. Marked `ponytail:` — a multi-process
  deployment gets a per-process allowance, which for an admin-pressed button is
  a cost ceiling, not a security boundary.

- **`modelExists` means "the endpoint accepted the configured model id".** An
  endpoint that silently serves a different model than it was asked for cannot
  be caught without a second, model-reporting round trip that no provider
  guarantees. The field is honest about acceptance, and the comment at the call
  site says so rather than implying identity.

- **A failure class the five fields cannot express does not get invented into
  them.** An unclassifiable provider error (a 500, a malformed body) leaves the
  fields at what was actually established and puts the reason in a `detail`
  string, redacted through `ProviderSecrets.redact` (M7.2). Admins already see
  the base URL on `AdminConnection`, so `detail` adds no exposure the shape did
  not already have — but it never carries key material.

- **The provider-error classifier lands here and M7.9 reuses it.** `#27` needs
  the same four classes (unreachable / unauthenticated / model-not-found /
  other) for its operator log line. One classifier, in
  `apps/api/src/providers/provider-error.ts`, keeps the two from drifting into
  two different vocabularies for one set of failures.

## Plan

1. `packages/contracts`: `ConnectionTestResult`, and `lastTest` on
   `AdminConnection` (nullable). Host shape untouched. — AC-1, AC-8
2. `provider_connections.last_test_result jsonb`, `pnpm db:generate`, commit SQL
   + snapshot. — AC-8, AC-12
3. `providers/provider-error.ts`: classify an unknown thrown provider error into
   the four classes plus a redactable detail. — AC-2, AC-3, AC-5
4. Extract `sourceFromRow` onto `ProviderConnectionsService`; `DmProviderSource`
   calls it. — AC-1 (the path under test is the path a turn uses)
5. `providers/connection-test.service.ts`: the bucket, the minimal call, the
   field mapping, the row write. — AC-1..AC-7
6. `POST admin/providers/:id/test` behind the existing `AdminGuard`. — AC-10
7. `apps/api/test/connection-test.e2e.test.ts` against local mock endpoints, one
   per class, plus the rate limit, the 403, and the no-key assertion. — AC-1..AC-11
8. Full suite, `db:check`, typecheck/lint/format. — AC-12

Two findings that came out of writing this rather than out of the issue, both
kept: the provider's error text is capped at 500 characters after redaction
before it is stored (a hostile endpoint otherwise gets an unbounded write into a
row an admin page renders), and `DmProviderSource` was refactored onto the
shared `sourceFromRow` so the test cannot drift from the path a turn takes.
