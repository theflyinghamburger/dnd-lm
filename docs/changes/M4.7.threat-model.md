# M4.7 threat model — character import from PDF

The change adds a new **file upload** reaching a **third-party parser**, on a
route that creates game state. Three boundaries move; nothing else does.

## 1. Untrusted file into a parser

An uploaded PDF is attacker-controlled input handed to `unpdf` (pdf.js). A
malicious or malformed file is the primary new exposure.

| Risk | Control |
|---|---|
| Memory exhaustion from a huge upload | `FileInterceptor` `limits.fileSize` = 8 MB, enforced by multer **before** the body is materialised, and `files: 1`. A character sheet is a handful of pages; the real example is 1.6 MB. |
| Decompression bomb inside a small file | Not fully mitigated. pdf.js streams and the page loop is bounded by `numPages`, but a crafted object graph can still cost CPU. Accepted: the route is authenticated *and* campaign-membership-gated, so this is not anonymously reachable. Revisit if uploads ever open to non-members. |
| Parser crash taking down the request | Every `getDocumentProxy` failure is caught and answered as `PDF_UNREADABLE`. The parse runs inside the request, so a hang is a slow request rather than a corrupted state — nothing is written until the mapping succeeds. |
| Non-PDF content sniffed as a PDF | `looksLikePdf` checks the `%PDF-` magic bytes. The client-declared MIME type is never trusted; the e2e sends non-PDF bytes under `application/pdf` and expects a refusal. |
| A file that is a valid PDF but not a sheet | Refused as `NOT_A_CHARACTER_SHEET` on the absence of `CharacterName`, before any partial character is written. |

## 2. Untrusted values into game state

Field values are attacker-controlled strings even in a well-formed sheet — a
player can type anything into a form field before exporting.

| Risk | Control |
|---|---|
| Injecting a derived value (a made-up proficiency bonus, passive score, initiative) | Structurally impossible: the mapping reads a fixed list of input fields and builds the sheet from those. Every derived number is recomputed by `deriveSheet` (D-3, FR-401). `CharacterSheet` is `.strict()`, and the PDF path parses through the same schema as the JSON path — asserted by "imports no derived value from the file". |
| Out-of-range stats (STR 400, AC 9999, level 40) | The schema's bounds apply unchanged, because both import paths cross it. The total-level refinement caps a multiclass character at 20. |
| Unbounded strings or lists filling the row | Every mapped string is length-capped at the mapper and again by the schema; `inventory`, `attacks` and `spells` are capped at 200 / 40 / 400 entries. |
| A wrong-level import skewing every future roll | The sheet's own `ProfBonus` is compared against the parsed class line, and a disagreement refuses the import (AC-9). |
| Sheet text reaching the DM prompt as instructions | Unchanged by this work: a character sheet already reaches the DM through the `state` context layer, which is assembled server-side from typed fields, not pasted prose. The free-text fields that could carry an injection — features, actions, personality — are exactly the ones **not** imported. |

## 3. Authorization and disclosure

| Risk | Control |
|---|---|
| Importing into a campaign you are not in | `CampaignMemberGuard` on the controller class, unchanged; the campaign is a route parameter, never a body field, so the guard sees what the write uses. Asserted by "refuses someone who is not a member". |
| Importing a character owned by someone else | The owner is `@CurrentUser()`, never a request field — the same rule the JSON route follows. |
| The uploaded file being retained | It is not. The buffer is parsed in-request and never written to disk or the database; only the mapped sheet is stored. Nothing to leak later, and no retention question to answer. |
| Sheet contents in logs | Nothing logs field values. Refusals carry the offending *field name* and, for the level mismatch, the class line and two bonus numbers — no character data beyond what the uploader just sent. |

## Residual, accepted

- **CPU cost of a crafted PDF** (above). Authenticated and membership-gated; no
  rate limit specific to this route beyond the app's existing ones.
- **`unpdf` is new third-party code in the API's dependency tree.** It bundles
  pdf.js. `renderPageAsImage` — the one entry point that would pull the native
  `@napi-rs/canvas` — is never called, so the optional native dependency stays
  uninstalled.

## 4. The two new write paths (M4.7 follow-ups)

| Risk | Control |
|---|---|
| Deleting someone else's character | Owner, or a host/admin **of that campaign**. A character in another campaign returns the same 403 as one you do not own, so neither is probeable (FR-105). |
| Deleting a character mid-turn, stranding an open roll | `pending_actions.authorized_character_ids` is a bare `uuid[]` with no foreign key, so the delete is refused with `CHARACTER_HAS_OPEN_ACTION` while the character is named in an **open** one. Closing the action unblocks it. |
| Losing roll provenance | Not possible: `rolls.character_id` is `ON DELETE SET NULL`, so the roll, its dice and its modifier breakdown survive the character (FR-302). Asserted. |
| A client bypassing the level check by always sending the override | `?confirmLevel=N` is honoured only when `N` equals the level just parsed from the class line. A client that sets it blindly gets the same refusal, so the override cannot become a default someone forgets they enabled. This echo is the control; a boolean flag would not have been one. |
| The override hiding a misparse | It does not suppress the check, only that one instance of it, and the refusal it follows names the parsed level, the stated bonus and the derived bonus. The decision is recorded in the request. |

## 5. Reading stored sheets

Replacing `row.sheet as CharacterSheet` with `parseStoredSheet` **narrows** the
trust boundary rather than widening it: the column was previously asserted to have
a shape nobody checked, on every read path including the DM's. It is now parsed
against the same `.strict()` schema an import crosses.

A structurally corrupt row therefore raises at the read boundary. The caller gets
a bare 500 and learns nothing about the sheet's shape — a corrupt stored row is an
internal fault, and disclosing its structure would be the wrong answer to it. The
field name reaches the operator log only. Asserted both ways.
