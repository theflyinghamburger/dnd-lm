## Change brief

A failed DM turn has two audiences and today serves one of them properly.

The **player** already gets a static per-reason sentence, deliberately not the
provider's text — that property exists (M6.7) and this change keeps it and adds
the tests that hold it in place. The **operator** gets whatever the ad-hoc
`logger.error` calls happened to emit: `graph run failed:` with a stack in one
place, `resolution N not committed:` in another, and for a rejected credential —
the single most common misconfiguration — nothing at all beyond a stack, because
a 401 thrown by the SDK escapes the graph and is reported as `INTERNAL`.

So the operator cannot tell DNS from auth from a wrong model id with one grep,
which is the whole ask of #27. This change classifies provider failures before
they become a `DmCompletion`, maps them onto the closed client-facing enum
without growing it, and emits one structured, redacted line per failed
resolution.

It also writes down the rule that must not quietly change: **no automatic
fallback**. A failed connection is never retried on another connection, in this
turn or a later one. A silent model switch mid-session is a continuity bug
dressed as resilience.

## Specification

AC-1  A provider failure is classified before it becomes a failure the client
      sees: connection refused / DNS / timeout, 401 or 403, and an unserved
      model id all emit `PROVIDER_ERROR`; no selection and a disabled
      connection emit `NO_PROVIDER`. `DmFailureReason` does not grow.
AC-2  The `DM_RESOLUTION_FAILED` `message` is the static per-reason string and
      contains none of: the configured base URL, the key, the model id, the
      SDK's error text — asserted for each failure class (FR-505, NFR-305).
AC-3  Exactly one operator line is emitted per failed resolution, in one
      format, carrying the reason, the fine-grained class, the resolution id,
      the session id, the connection id, the model id, and the provider's
      detail.
AC-4  That line's detail passes through M7.2 redaction: a provider that echoes
      the key back produces a line containing `[REDACTED]` and not the key.
AC-5  No automatic fallback: with two enabled connections and the campaign's
      selection failing, the other connection's endpoint records zero calls
      across the failed turn, and the campaign's selection is unchanged after.
AC-6  An unparseable control block still maps to `INVALID_OUTPUT` — the M6.3
      contract-suite behaviour is unchanged by this change.
AC-7  `pnpm test` green against live Postgres, `pnpm db:check` clean,
      typecheck / lint / format green.

## Decisions

- **The catch goes in `callDm`, not in each adapter.** Both adapters throw
  their SDK's own error type and a local endpoint throws undici's; one catch at
  the single call site covers all three, and the graph's existing bounded retry
  then owns what happens next. Putting it in the adapters would mean two
  implementations of one rule and a `DmCompletion` shape each could interpret
  differently.

- **The class vocabulary is M7.5's `ProviderFailureClass`**, plus the
  no-provider reasons (`no_selection`, `disabled`, `connection_missing`,
  `url_rejected`). M7.5 (#23) already had to name these four classes to report
  its per-field test result; a second vocabulary for the same failures is how
  two subsystems end up disagreeing about what "unreachable" means.

- **The no-provider reason is resolved by a diagnostic read on the failure path
  only.** `DmProviderSource.get` still returns `SourcedProvider | null` — making
  it return a reason would change the DI seam every DM test overrides, for a
  string that appears in a log line. The orchestrator re-reads the campaign's
  selection when it is about to report `NO_PROVIDER`, and that read never
  influences control flow.

- **The ad-hoc failure logs are folded into the one function.** `graph run
  failed:` and `resolution … not committed:` are removed, not kept alongside:
  "one format, not N" is the requirement, and two lines per failure would make
  a per-class count wrong.

- **A rejected credential is still retried once.** `PROVIDER_ERROR` gets the
  same single bounded retry the graph gives any provider error (M6.7). Skipping
  the retry for 401 would be a new policy, and #27 does not ask for one; the
  cost is one wasted call on a misconfigured connection.

- **Both halves of the message/payload split are asserted.** See CL-001: the
  static sentence must stay clean, and the attribution fields must stay
  present. A test for each, so collapsing them fails loudly.

## Plan

1. `DmFailure` carries the fine-grained class; `callDm` catches, classifies,
   and redacts. — AC-1, AC-2
2. `DmAttribution` carries the class and detail the operator line needs. — AC-3
3. `logResolutionFailure` in the orchestrator, called from `reportFailure`; the
   ad-hoc lines removed. — AC-3, AC-4
4. `explainNoProvider` for the `NO_PROVIDER` classes. — AC-1, AC-3
5. The no-fallback rule stated where the connection is chosen. — AC-5
6. Tests: one per failure class against local mock endpoints, the operator-line
   assertions, the no-fallback test with two endpoints, and the unchanged
   `INVALID_OUTPUT` path. — AC-1..AC-6
7. Full suite, `db:check`, typecheck / lint / format. — AC-7

Review follow-up: AC-2 says "for each failure class" and the first cut asserted
the message only for the unauthenticated one. `expectNoLeak` now runs on every
class the suite produces. And the `model` field on the operator line — the only
field that is admin-typed free text — is reduced to a charset that cannot open
a field, so a model id like `evil" class=unauthenticated` can neither blur nor
forge one. A test asserts exactly that.

Worth noting for review: three ad-hoc failure logs were **removed**, not kept
alongside the new one (`graph run failed:`, `graph resume failed:`, `resolution
… not committed:`). Their detail is now a field on the single line, which is
what makes a per-class count possible.
