## Change brief

M8 (#9) gives the DM hand-written campaign notes; M8.1 (#48, stacked base) built
the `campaign_notes` table. This subtask (#49) is the query layer over it:
`NotesService.retrieve({ campaignId, query, maxSpoilerLevel, chapter, tokenCap })`
returning `{ slug, title, body }[]` in `ts_rank` order under a token cap. Today
nothing reads the table.

The property that matters is invariant 7: campaign, published status, spoiler
level and chapter are `WHERE` predicates in the ranking statement, so no row
outside the reader's scope is ever ranked. No DM wiring (M8.3), no roster
(M8.4), no HTTP surface (M8.5).

## Specification

AC-1  A note in campaign A is never returned for campaign B, for a query it
      matches best, with identical text in both (FR-608).
AC-2  A note with `chapter` above the passed party chapter is never returned for
      a query it matches best; at that chapter it is returned. A note with
      `chapter` NULL is returned at chapter 0.
AC-3  A `dm` note is never returned when `maxSpoilerLevel` is `player`; the same
      note is returned at `dm` (FR-608).
AC-4  A `draft` note is never returned, at `dm` level and any chapter
      (docs/campaign-pdf-ingestion.md §3.2).
AC-5  More out-of-scope best matches than the candidate limit do not crowd out a
      weaker in-scope match — the filters run before rank and limit.
AC-6  Results are ordered by `ts_rank` (a title match outranks a body match) and
      every row carries `slug` and `title` (FR-609).
AC-7  Notes summing past `tokenCap` are cut to the highest-ranked prefix that fits,
      measured with `estimateTokens(title + body)`; no note is truncated (FR-609).
AC-8  `NotesModule` is registered in `AppModule`; build/typecheck/lint/format/test
      green against live Postgres.

## Decisions

- **`plainto_tsquery`, per #49**, not the `websearch_to_tsquery` in
  docs/campaign-pdf-ingestion.md §3.2. Both AND every term and neither errors on
  user text; the issue is the more specific source. Flagged in the PR: M8.3 keys
  retrieval on free trigger text, and AND-of-all-words will match little there —
  M8.3 should decide the query shape (e.g. OR of terms via `to_tsquery`).
- **The caller passes `chapter`**, per #49's signature. Reading
  `settings.progression.chapter` (absent → 0) is M8.3's job at the call site.
- **Stop at the first overflowing note**, per #49 ("accumulating and stopping").
  The result is always a rank-order prefix; one oversized top note yields `[]`.
- **`LIMIT 20` candidates** before the cap ("top-N", MVP.md M8.2). The cap is the
  real ceiling; the limit only bounds the fetch. Ties break on `slug` so order
  is deterministic.
- **A whole note is the retrieval unit** (marked `ponytail:` in the code).
- **Profile `standard`**, raised from the path floor (`fast`): the change is a
  spoiler/cross-campaign data boundary. No schema, auth or contracts paths.
- **Citation is `{slug, title}`** per #49; the design doc's `source.book/pages`
  arrives with Phase 4 sources.
- **AC-5 was checked against a mutant**: deleting the `status` predicate fails
  both the draft test and the crowd-out test.
