## Change brief

`PATCH /campaigns/:campaignId/triggers` (M3.2, host/admin) is the mechanism
behind MVP.md §4.3 rule 7 — a disabled trigger behaves exactly like an unknown
tag — and nothing in `apps/web` calls it. A host can only exercise it with curl.

This adds `api.updateTriggers` and a checkbox per registry entry inside the
existing host/admin `CampaignSettings` panel, seeded from and invalidating the
`['triggers', campaignId]` query `Chat` already reads, so the composer's
autocomplete and routing preview follow the toggle without a reload. Each row
names the tag and what it does; the roll-resume row carries its warning.

Profile raised from the `fast` floor (web-only paths) to `standard`, matching
`pregen-picker`: user-visible behaviour on an authorization-gated write.

## Specification

AC-1  `api.updateTriggers(campaignId, body)` sends `PATCH /campaigns/:id/triggers`
      with `{ triggers: Record<id, boolean> }`.
AC-2  With `dm_mention` disabled in the triggers response, the registry the
      composer uses omits `@dm`, and `parseMessage('@dm …')` against it previews
      as a `table` route with no `dmTrigger`; with it enabled, it previews as a
      `dm` route carrying `dm_mention`.
AC-3  Before the triggers query resolves, the composer's registry is empty.
AC-4  Every `TRIGGER_REGISTRY` entry has a description label, and no label exists
      for an id outside the registry.
AC-5  `pending_action_completed` carries a warning that a parked DM turn never
      resumes from a roll while it is off; the checkbox is not blocked.
AC-6  The toggle list renders every entry the server returns, host-scoped
      `host_turn` included, and only inside the host/admin settings panel.
AC-7  On a settled toggle the client invalidates `['triggers', campaignId]`; no
      new query key is introduced.
AC-8  A player's forged PATCH is refused with 403 (existing
      `routing.e2e.test.ts` "refuses a player changing them").

## Decisions

- D-1  Pure logic tests only, per epic #72 / `pregen-picker.md` D-5: no DOM
  testing library. The registry filter `Chat` used inline moves to
  `apps/web/src/triggers.ts` (`enabledRegistry`) so AC-2/AC-3 test the code the
  composer actually runs rather than a copy. AC-6/AC-7 are component wiring,
  checked by reading and by hand.
- D-2  Each checkbox writes immediately (one id per PATCH), like the provider
  select beside it — no save button. The fieldset is disabled while a write is
  in flight so two quick clicks cannot race.
- D-3  Invalidate on settle, not only on success: a refused write must snap the
  checkbox back to the server's state.
- D-4  The server side of rule 7 (a disabled `@dm` wakes no DM; 403 for a
  player) is already covered by `routing.e2e.test.ts`; not duplicated.

## Plan
