# Migration plan — M7.5

`apps/api/drizzle/0007_soft_blue_blade.sql`:

```sql
ALTER TABLE "provider_connections" ADD COLUMN "last_test_result" jsonb;
```

**Shape.** One nullable `jsonb` column holding the latest
`ConnectionTestResult`. No default, no backfill, no index: every existing row
reads as "never tested", which is true.

**Lock.** `ADD COLUMN` of a nullable column with no default takes a brief
`ACCESS EXCLUSIVE` lock and rewrites nothing (PostgreSQL 11+). On a table that
holds one row per configured provider, the pause is not measurable.

**Order.** Additive and back-compatible in both directions: the previous build
ignores a column it does not select, and this build reads `null` from a row the
previous one wrote. Deploy order does not matter, which is what makes the
rollback below cheap.

**Verification.** `pnpm db:migrate` then `pnpm db:check` (CI's drift check runs
the same comparison against the committed snapshot). The M7.5 e2e suite asserts
a fresh connection reads `lastTest: null` and that a test press makes the admin
reads carry the stored result.
