## Change brief

M5.6 shipped `HOST_CONTROL` (PAUSE / RESUME / END / FORCE_DM_TURN) and M5.5
`REQUEST_ROLL` in the gateway, both host-checked server-side (`NOT_THE_HOST`),
but the web client never sends either (summary.md §6, "No host-control UI").
A host cannot pause, resume, end, force a DM turn or ask for a check from a
browser (FR-801, FR-106, M5.5).

Client-only: two command senders on `useSession`, a `HostBar` above the
composer, and a pure gate in `status.ts`. No server, contract, or schema change.
The state change reaches every window through U1.0's `SESSION_STATE_CHANGED`
fold; a request's card through U1.1's `PendingRollCard`.

## Specification

AC-1  `hostActions(status)` (`apps/web/src/session/status.ts`, pure) enables
      PAUSE iff `canTransition(status, 'PAUSED')`, END iff
      `canTransition(status, 'SESSION_ENDED')`, RESUME iff `status === 'PAUSED'`,
      the check form iff `acceptsMutations(status)` and
      `canTransition(status, 'WAITING_FOR_ROLL')` (PAUSED -> WAITING_FOR_ROLL
      is RESUME's edge, not a request's), and
      FORCE_DM_TURN iff `acceptsMutations(status)` — so it is off while paused
      and after an end (summary.md §4: a pause blocks all triggers). Unit-tested
      against every `SessionState` (FR-801).
AC-2  `useSession` returns `hostControl(action)` and
      `requestRoll(prompt, expression, characterIds)`, each sending a fresh
      `command_id` with the `stateVersion` ref, `absorb`ing the result, and
      returning the ack or `ServerError` (FR-801, M5.5).
AC-3  `HostBar` renders only when the viewer's roster role — one `const` in
      `Chat`, shared with the routing preview — is `host` or `admin`. The server
      refusing a player with `NOT_THE_HOST` stays the control (FR-801).
AC-4  End takes two presses: End, then Confirm end (with Cancel), the inline
      pattern from `AdminProviders.tsx`.
AC-5  The check form lists campaign characters as checkboxes from the shared
      `['characters', campaignId]` query (no new fetch) and sends
      `REQUEST_ROLL`; the resulting `ROLL_REQUESTED` renders as U1.1's card
      (FR-305). Prompt/character caps are not re-derived client-side.
AC-6  Every rejection from either sender is rendered as `code: message` in a
      `role="alert"` element — the server's own words.
AC-7  typecheck / lint / format / test green, integration suite against live
      Postgres.

## Decisions

- **D-1 — Rejections render `code: message`, not through `describeApiError`.**
  The issue names `describeApiError`, but that formats HTTP `ApiError`s; a
  socket rejection is a `ServerError` whose `message` is already the server's
  sentence. Rendering it directly is the same intent without a second adapter.
- **D-2 — RESUME is gated on `status === 'PAUSED'`, not `canTransition`.** Its
  target is the server's `pausedFrom`, which the client does not hold; "only
  legal from PAUSED" is exactly the check.
- **D-3 — FORCE_DM_TURN is gated on `acceptsMutations`.** The server runs it in
  `mutation` mode, which refuses both PAUSED and SESSION_ENDED; "not paused"
  alone would offer it on an ended session.
- **D-4 — No client-side caps**, per the issue: a prompt over 200 chars or more
  than 12 characters is refused by the server (`INVALID_PAYLOAD`) and that
  refusal is shown. Submit is disabled only with no character ticked.
- **D-5 — Tests.** Pure gate unit-tested; the bar driven by hand (epic #72: no
  DOM testing library). The server paths are already covered in
  `apps/api/test/orchestrator.e2e.test.ts` "host controls (M5.6, FR-801)":
  RESUME to the interrupted state, FORCE_DM_TURN refused while paused and
  `NOT_THE_HOST` for a player, END freezing mutations.
- **D-7 — A third outcome: no answer.** `command()` returns `null` when there
  is no socket or `emitWithAck` rejects (it does whenever the socket drops
  mid-flight); `HostBar` shows "Not connected" for it rather than nothing.
  `HostBar` also sends one command at a time: a double press would quote the
  same version and the second would be refused right after the first landed.
- **D-6 — Replay is not gap-free** (pre-existing, #94's PR body): a transition
  in the lost tail is missed until reload. Inherited, not fixed here.
