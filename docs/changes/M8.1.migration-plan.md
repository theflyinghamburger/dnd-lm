# Migration plan — M8.1

`apps/api/drizzle/0010_dry_marrow.sql` (generated by `pnpm db:generate`, not hand-edited):

- `CREATE TYPE note_spoiler_level AS ENUM ('player','dm')`,
  `note_status ('draft','published')`,
  `note_type ('location','npc','quest','item','lore','handout')`.
- `CREATE TABLE campaign_notes (…)` with
  `tsv tsvector GENERATED ALWAYS AS (setweight(to_tsvector('english', coalesce(title,'')),'A') || setweight(to_tsvector('english', coalesce(body_md,'')),'B')) STORED`.
- FK `campaign_notes_campaign_id_campaigns_id_fk … ON DELETE cascade`.
- `campaign_notes_campaign_slug_key` unique btree `(campaign_id, slug)`,
  `campaign_notes_campaign_type_idx` btree `(campaign_id, type)`,
  `campaign_notes_tsv_idx` gin `(tsv)`.

**Shape.** New enums and a new, empty table. Nothing existing is altered: no
rewrite, no lock on a table anything reads, no backfill. The previous build
does not know the table exists and is unaffected, so the order of deploy vs.
migrate does not matter.

**`campaigns.settings.progression.chapter`** is a documented key in existing
JSONB, not a schema change. No writer exists yet; absent means "no chapter
reached".

## Hazard: changing the tsvector expression later

If a later change edits the `generatedAlwaysAs` expression, drizzle-kit emits
`DROP COLUMN tsv` + `ADD COLUMN tsv …`. Postgres drops `campaign_notes_tsv_idx`
together with the column, and drizzle-kit's index diff sees no change (same
name, same snapshot definition), so it does **not** recreate it. **The GIN
index is silently lost** and full-text retrieval degrades to sequential scans.
Anyone changing the expression must add a follow-up that recreates the index
(e.g. rename the index in `schema.ts` in the same change so the diff emits a
fresh `CREATE INDEX`), and verify with `\d campaign_notes`.

Related rules for the expression (all load-bearing): no `${}` interpolation
(drizzle-kit renders qualified names / `$1`, invalid in a generated column);
the two-arg `to_tsvector('english', …)` (the one-arg form is not immutable);
the index must stay explicitly named.

## Parallel-branch collision

Another branch may also generate a `0010_*` migration. Whichever merges second
must rebase, delete its generated migration and snapshot, and regenerate so
the journal stays linear. Two `0010` files would not conflict textually but
would fork the snapshot chain and fail CI's drift check.

## Verification

`pnpm db:migrate` on live Postgres, `pnpm db:check`, CI's
regenerate-and-diff drift job, and `apps/api/test/campaign-notes-storage.e2e.test.ts`
(generated column populated, GIN index usable, unique-per-campaign slug,
cascade on campaign delete, enum order, defaults).
