## Change brief

`useSession.applyEvent` drops `SESSION_STATE_CHANGED`, so `snapshot.status` is
frozen at whatever `resume` returned. A paused or ended session keeps looking
live, with an enabled composer, until someone reloads (NFR-205). The gateway
(`session.gateway.ts:628`) and orchestrator (`orchestrator.ts:399`) already
broadcast `{ action, from, to }`; this is client-only. No new event, command,
or backend change, and nothing in `packages/contracts`.

## Specification

AC-1  `applyEvent` applies `SESSION_STATE_CHANGED` by setting `snapshot.status`
      to `payload.to`, after the high-water-mark guard, so a replayed change at
      or below the mark does not re-apply. The header shows the new status
      without a reload, and a resume shows whatever `to` says.
AC-2  `canSend(status, draft)` (`apps/web/src/session/status.ts`) gates the
      Send button: while `PAUSED`, an untagged message sends, but a draft with
      a `dmTrigger` and a `/roll` do not; in `SESSION_ENDED` nothing sends; in
      live states everything the router accepts sends. The gate is
      `acceptsMutations`/`isTerminal` from contracts, never a local state list.
AC-3  The sheet's roll buttons are disabled while
      `acceptsMutations(status)` is false.
AC-4  A banner (`role="status"`) says in words which state it is in, with
      different text for `PAUSED` and `SESSION_ENDED` (NFR-403), and nothing
      in live states.
AC-5  While `status === 'DM_GENERATING'` the transcript's `aria-live` region
      shows "The Dungeon Master is thinking…"; it clears when the server moves
      the status on (commit or failure both emit `SESSION_STATE_CHANGED`).
AC-6  After `SESSION_ENDED` the input is disabled and the transcript stays
      rendered.
AC-7  typecheck / lint / format / test green.

## Decisions

- **D-1 — A `/roll` typed into chat counts as a roll.** The gateway runs it
  as `ROLL_DICE` in `mutation` mode (`session.gateway.ts`, `recipientType ===
  'dice'`), so the server would refuse it while paused anyway. `canSend`
  reads it from the same routing preview as `dmTrigger`, no second parse.
- **D-2 — Ended sessions refuse chat client-side.** The server still accepts
  `chat` mode after `SESSION_ENDED`; the issue's exit criterion is "after END,
  nothing sends", so the client gates on `isTerminal`. No server change.
- **D-3 — Nothing sends before the first snapshot.** The gate needs a status;
  before `resume` answers there is none.
- **D-4 — Reuse for U1.1/U1.2.** The live status stays on `snapshot.status`
  from `useSession`; the pure gates live in `session/status.ts` for #74/#75 to
  import. HP buttons are HTTP, not session commands, and are unchanged.
- **D-5 — Tests.** Pure gate logic is unit-tested through the real
  `parseMessage`; click-throughs by hand (epic #72: no DOM testing library).
