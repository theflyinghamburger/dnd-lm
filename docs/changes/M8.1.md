## Change brief

M8 (#9) gives the DM hand-written campaign notes to narrate from; this subtask
(#48) is only the table the rest of M8 builds on. Today there is no notes
storage at all — hosts type strings into `campaigns.settings.notes`, a shim
retrieved by substring match.

The one thing this has to get right is the shape. MVP.md M8.1 and
docs/campaign-pdf-ingestion.md §3.1 both say Phase 4 ingestion writes into this
table *without a migration*, so every column ingestion needs is added now. No
service, no controller, no retrieval, no contracts change (M8.2–M8.5).

## Specification

AC-1  A Drizzle migration + snapshot creates `campaign_notes(id, campaign_id →
      campaigns.id ON DELETE CASCADE, slug, type, title, body_md, frontmatter
      jsonb NOT NULL DEFAULT '{}', spoiler_level, chapter integer NULL, status,
      source_id, tsv tsvector GENERATED ALWAYS AS … STORED, created_at,
      updated_at)`; `pnpm db:check` is clean and CI's regenerate-and-diff drift
      check produces no change.
AC-2  Enums `note_type` (`location, npc, quest, item, lore, handout`),
      `note_spoiler_level` (`player, dm` — in that order, with a comment saying
      the order is load-bearing), and `note_status` (`draft, published`).
AC-3  `tsv` is populated by an `INSERT` that never mentions it, with the title
      at weight A and the body at weight B.
AC-4  `EXPLAIN` of a `tsv @@ plainto_tsquery(...)` predicate can use the GIN
      index `campaign_notes_tsv_idx`.
AC-5  A duplicate slug in one campaign is rejected; the same slug in two
      campaigns is accepted.
AC-6  Deleting a campaign deletes its notes and only its notes (FR-611).
AC-7  `spoiler_level <= 'player'` returns `player` notes and not `dm` notes.
AC-8  A note inserted with only the required fields is `spoiler_level = dm`,
      `status = published`, `chapter` null, `source_id` null, frontmatter `{}`.
AC-9  `campaigns.settings` doc comment names `progression.chapter` as the
      party's current progression marker; no new column for it.
AC-10 typecheck / lint / format / test green against live Postgres.

## Decisions

- **`status` and `source_id` are in this migration**, though #48's column list
  omits them. docs/campaign-pdf-ingestion.md §3.1 puts them here explicitly,
  and P4.1.1 (#66) and P4.1.3 (#68) both list #48 as the provider of
  `campaign_notes.status`/`source_id`. Leaving them out would force the exact
  migration M8.1 exists to avoid. `status` defaults to `published`, so M8's
  hand-authored notes are unaffected by the column's existence.
- **`source_id` has no foreign key yet.** Its target, `campaign_sources`, is
  created by P4.1.1. Creating that table here would pull P4.1.1's scope (and
  its bytea upload column) into M8. So P4.1.1 adds one constraint-only
  `ALTER TABLE campaign_notes ADD CONSTRAINT … ON DELETE SET NULL` — no column,
  no rewrite. This is a slight softening of "no migration to this table": the
  *columns* ingestion writes are all here; the referential constraint is added
  by the change that creates the referenced table. Flagged in the PR.
- **`spoiler_level` defaults to `dm`** (ingestion design §3.1): an unlabelled
  note fails toward hidden, never toward spoiled.
- **`body_md` is `NOT NULL DEFAULT ''`**, so a stub note (title only) is valid
  and the tsv expression never sees a null. `coalesce` stays in the expression
  anyway as the design specifies.
- **The architecture.md §9 keys that are not filter columns** (`source`,
  `unlock_condition`, `entities`, `connections`, and ingestion's `aliases`)
  live in `frontmatter`. §9's `id` is `slug`; `campaign` is `campaign_id`.
- **No `truncateAll` change.** `campaign_notes` cascades from `campaigns`,
  which the harness already truncates with `CASCADE`.
- **The GIN-index test disables seq scans in one transaction.** A two-row
  table never picks an index on cost, so the test proves the index *can*
  answer the predicate — the property M8.2 relies on.
- **Drizzle emitted the generated column and GIN index without hand edits.**
  No hand-written SQL.
