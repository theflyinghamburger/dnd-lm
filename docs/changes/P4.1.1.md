## Change brief

P4.1 (#64) turns an uploaded campaign PDF into draft `campaign_notes`. This
subtask (#66) is only the upload half: the `campaign_sources` table, a
host-or-admin multipart endpoint with list/get/delete, and the trust boundary
in front of it (architecture.md §11, invariant 7). No text extraction, no LLM
call, no worker — an uploaded source sits at `pending`, which is correct until
P4.1.2–P4.1.4 land. It also adds the `campaign_notes.source_id` foreign key
that M8.1 (#48) deferred because its target did not exist yet.

## Specification

AC-1  A Drizzle migration + snapshot creates enum `source_status` (`pending,
      extracting, review, failed`) and `campaign_sources(id, campaign_id →
      campaigns ON DELETE CASCADE, filename, byte_size, sha256, content bytea,
      status DEFAULT pending, error, pages_total, pages_done DEFAULT 0,
      notes_extracted DEFAULT 0, uploaded_by → users, created_at,
      finished_at)`, and adds `campaign_notes.source_id → campaign_sources(id)
      ON DELETE SET NULL`. `pnpm db:check` is clean.
AC-2  `POST /api/campaigns/:campaignId/sources` (multipart field `file`) by a
      host stores the file and returns 201 with a `pending` row whose
      `byte_size` and `sha256` match the file; the stored bytes equal the file.
AC-3  A non-host member gets 403 on upload, list, get and delete (NFR-302).
AC-4  Non-PDF bytes are refused 422 `NOT_A_PDF` whatever the filename or the
      declared MIME; PDF bytes declared as a non-PDF MIME are refused 422.
AC-5  A file over 32 MB (tested at 40 MB) is refused 413 by multer's limit and
      nothing is stored.
AC-6  No response body from any of the four endpoints contains `content`, on
      any status code; success bodies parse under `CampaignSource.strict()`.
AC-7  A second upload while the campaign has a `pending`/`extracting` source is
      409 `SOURCE_IN_FLIGHT` naming that source; two concurrent uploads yield
      exactly one 201 and one 409.
AC-8  Deleting a campaign deletes its sources only; deleting a source leaves its
      notes with `source_id IS NULL`.
AC-9  Get/delete of another campaign's source id is 404; a malformed id is 400.
AC-10 Contracts export `SourceStatus` and `CampaignSource` (no `content` field).
AC-11 typecheck / lint / format / test green against live Postgres.

## Decisions

- **One-in-flight is a partial unique index**
  (`campaign_sources_one_in_flight_key ON (campaign_id) WHERE status IN
  ('pending','extracting')`), not a check-then-insert, so two racing uploads
  cannot both land. The service catches the 23505 and answers 409 with the
  in-flight row. A DB constraint over app code; covered by a concurrency test.
- **`uploaded_by` is nullable, `ON DELETE SET NULL`.** The issue gives no
  delete rule. `CASCADE` would let deleting a co-host's account delete the
  campaign's book; SET NULL keeps the book and redacts the uploader — the
  `provider_connection_audit.actor_user_id` precedent.
- **Magic-bytes check reuses `looksLikePdf`** from `characters/pdf-form.ts`
  (#81's character upload), and the refusal is the same 422 `NOT_A_PDF`; the
  size cap is multer's `limits.fileSize` exactly as there, so an oversize
  upload is 413 before the buffer exists.
- **The `api.ts` FormData fix is already on the base** (landed with the
  character PDF upload), so no web change here.
- **`filename` is capped at 255 chars** and stored for display only.
- **Deleting a `pending` source is allowed** — it is the only way to clear a
  409 until the worker exists. Deleting mid-`extracting` is P4.1.4's concern.
- **`sha256` is lowercase hex text**, 64 chars, per the contract regex.
- **`truncateAll` lists `campaign_sources`** as the issue asks, though it
  also cascades from `campaigns`.
