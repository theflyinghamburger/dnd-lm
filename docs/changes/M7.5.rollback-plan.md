# Rollback plan — M7.5

**Code alone (no schema change).** Revert the PR. The column is left in place
and simply stops being written or read; nothing else in the schema references
it, and the previous build never selected it. This is the expected rollback and
needs no database work at all.

**Schema too, if the column must go:**

```sql
ALTER TABLE "provider_connections" DROP COLUMN "last_test_result";
```

Then delete `apps/api/drizzle/0007_soft_blue_blade.sql`, its snapshot entry, and
the `__drizzle_migrations` row for it, so `pnpm db:check` and the committed
migrations agree again. Do the code revert first: a build that still selects the
column fails every admin connection read once it is dropped.

**Data lost.** The cached last-test result per connection. It is a convenience
projection, recomputable by pressing *Test* again, and nothing else reads it —
no billing, no audit, no turn resolution. There is no history to preserve
because none is kept, by design (see the work item's Decisions).

**No forward-compatibility trap.** The column is written only by
`ConnectionTestService.test` and read only by `toAdmin`, which parses it through
`ConnectionTestResult.safeParse` and falls back to `null`. A row written by a
future shape does not break a rolled-back build.
