# Threat model: notes in the DM context layer (M8.3)

Campaign notes now flow from `campaign_notes` into every `resolve_action` and
`npc_dialogue` prompt. The asset is the DM turn's integrity (invariant 1, 7)
and the party's spoiler boundary (FR-608).

## Prompt injection via note text (invariant 7)

Note title and body are host-written today and book-extracted in Phase 4.
Controls: every note is rendered inside the one existing
`UNTRUSTED_BEGIN`/`UNTRUSTED_END` block, never in `system`; the system prompt
tells the model that text is data. A note could previously have closed the
block early by containing the end marker; runs of three or more angle brackets
in note text now collapse to two, so the marker cannot be forged. Even a model
that obeys an injection can only *propose*: proposals are validated and
committed by the orchestrator (invariant 1), so "grant 500gp" is at most an
`add_item` proposal subject to the same checks as any other. Tested: an
injected instruction plus forged marker stays inside the block, the prompt has
exactly one end marker, the turn commits with no proposals.

Residual: the model may still be persuaded in its *narration*. That is the
irreducible LLM risk invariant 7 accepts; the blast radius is prose.

## Spoiler leakage (FR-608)

The DM reads `dm`-level notes by design (#50). The progression boundary is the
`chapter` predicate, fed from `campaigns.settings.progression.chapter` read
server-side; a missing or malformed value reads as 0, the most restrictive.
Leakage to players then depends on the model not narrating DM-only facts — the
system prompt's "never reveal that you have seen beyond the current scene".
Residual: that line also calls the data "fiction the players can see", which is
inaccurate for `dm` notes; flagged as a follow-up (#50 froze the prompt).

## Cross-campaign leakage

`campaignId` is the trigger's, set by the orchestrator from the session row,
never from a client payload. The retrieval's `campaign_id` predicate (M8.2) is
in the ranking statement. Tested end to end: campaign B's better-matching note
never appears in campaign A's prompt.

## Model tool path (FR-503)

`search_campaign_notes` still has no DB handle; it filters the notes already
retrieved into the context package.

## Denial of service / budget

The query is the trigger text, bounded by message limits; `plainto_tsquery`
never errors on user text and the OR rewrite only swaps its operator. The
layer never exceeds `LAYER_BUDGET.notes` (tested at ~10x the cap), and
retrieval fetches at most 20 candidates.
