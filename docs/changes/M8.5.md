## Change brief

M8.1 (#90) created `campaign_notes`; nothing can write it yet except SQL. #52
adds the surface a host prepares a campaign through (FR-611): CRUD routes and a
web editor. A note carries `dm`-level content, so this is a read-authorization
surface before it is an editor — reads are host-or-admin exactly like writes.
It also makes `campaigns.settings.progression.chapter` host-settable (#52:
"Also settable … next to the DM knobs"), because the chapter gate is
decoration without it.

## Specification

AC-1  `packages/contracts` exports `NoteType`, `NoteSpoilerLevel`, `NoteStatus`
      (equal, in order, to the DB enums — asserted), `NoteSlug` (kebab-case),
      `CampaignNote`, `CampaignNoteSummary` (no body), `CreateNoteRequest`,
      `UpdateNoteRequest`. Both request schemas are `.strict()`; neither lets a
      client set `sourceId`, and the slug is not patchable.
AC-2  `GET|POST /api/campaigns/:campaignId/notes` and
      `GET|PATCH|DELETE /api/campaigns/:campaignId/notes/:slug` exist; the
      list carries no `bodyMd`; delete is 204; unknown slug is 404
      `NOTE_NOT_FOUND`.
AC-3  A player member gets 403 on every notes route, read and write, and a
      player's GET response contains no note content (FR-611, FR-105).
AC-4  A non-member gets 403 and an unauthenticated caller 401 on every route.
AC-5  A host (and a campaign `admin` member) creates, reads, edits and deletes
      a note in their own campaign; a host is refused (403) on another
      campaign's routes, and another campaign's slug through their own route
      is 404 with no content.
AC-6  A duplicate slug in one campaign is 409 `NOTE_SLUG_TAKEN` naming the
      slug; the same slug in another campaign succeeds.
AC-7  Every note write (create/patch/delete) calls
      `SessionContextService.invalidate(campaignId)`; reads do not.
AC-8  Publishing a draft is `PATCH { status: 'published' }` — no new endpoint
      (what P4.1.5 builds on).
AC-9  `PATCH dm-settings { progressionChapter }` writes exactly
      `settings.progression.chapter` (the key M8.3 reads), keeps sibling keys,
      `null` removes the key, negative is 400, a player is 403, and the write
      invalidates the campaign context; `GET dm-settings` returns it.
AC-10 `apps/web/src/CampaignNotes.tsx`: list, `<textarea>` body, selects for
      type / spoiler level / status, number input for chapter, reached from a
      host/admin-only "Notes" button in the lobby; `CampaignSettings.tsx` gains
      the chapter input in the existing knobs form. No new dependency.
AC-11 build / typecheck / lint / format / test green against live Postgres.

## Decisions

- **Own controller/service/module** (`apps/api/src/notes/notes-admin.*`, not
  `campaigns.controller.ts` as #52 suggests). Coordinator direction: M8.2 (#92)
  adds `notes.service.ts`/`notes.module.ts` on a sibling branch; separate files
  avoid a collision. `app.module.ts` may need a one-line merge with #92.
- **Guard and roles on the controller class**, not per method. Same
  `CampaignMemberGuard` + `@CampaignRoles('host','admin')`; the guard already
  reads class metadata (`getAllAndOverride`). A route added here later is then
  host-or-admin by default instead of member-readable by omission.
- **Plain DB writes**, no `runCommand` (#52, the M7.4 precedent): a note is not
  session state.
- **The list returns `status`, `sourceId`, `frontmatter`** (not the body):
  P4.1.5 groups drafts by source and shows the page citation from
  `frontmatter.source.pages` on each.
- **`sourceId` is never client-settable**; `.strict()` makes sending it a 400
  rather than a silent drop.
- **Slug is immutable** via PATCH: it is the URL key and the citation. Rename =
  delete + create.
- **Chapter is a number input, not a select** (#52 says "selects"). It is an
  open-ended non-negative integer; a select would need an invented upper bound.
  Empty = ungated (`null`), never 0.
- **`progressionChapter` rides on the existing dm-settings read/write** rather
  than a new endpoint (#52: "wire into the existing settings form rather than
  inventing a second one"). `null` deletes the key; M8.3 reads absent as 0.
- **Body capped at 100 000 chars, title 200, chapter ≤ 10 000.** Bounds, not
  product rules; Nest's JSON body limit caps the request anyway.
- **"Editing progression.chapter changes what retrieval returns on the next
  turn"** cannot be asserted here: retrieval (M8.2/M8.3) is not on this base.
  AC-9 asserts the exact key M8.3 reads (`settings.progression.chapter`,
  checked against `origin/m8.3-notes-in-context`) and the invalidation; the
  end-to-end assertion belongs with M8.3 once both merge.
- **Invalidation asserted by spying `SessionContextService.invalidate`** (#52
  allows "the trigger registry cache" when M8.4 is absent; the spy is the
  direct form of that).
- **409 carries a `reason`** so the web's existing `describeApiError` shows the
  server's own sentence naming the slug.

- **Review of d8c8043, both findings fixed:** a 404 now asserts
  `NOTE_NOT_FOUND`; a chapter `Number` cannot represent finitely (`1e999`) is
  sent raw so the schema refuses it instead of `JSON.stringify` turning it into
  `null` (red-first in `note-form.test.ts`), and both chapter inputs carry
  `max={10000}`.
