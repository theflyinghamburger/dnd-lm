# Threat model: campaign source upload (P4.1.1)

A new write endpoint that accepts an arbitrary file from a host and keeps it.
It is a trust boundary (architecture.md §11, invariant 7). Nothing in this
change parses the PDF past its first five bytes or sends it to a model.

## Who can reach it (NFR-302)

`CampaignMemberGuard` + `@CampaignRoles('host','admin')` on the controller
class, so all four routes share one rule and a new route inherits it. Guards
run before interceptors, so a non-host's multipart body is never parsed.
Non-members and non-hosts get the same 403, so campaign existence is not
probeable. Every query filters on the route's `campaign_id` — a host of
campaign B asking for campaign A's source id gets 404 (IDOR), tested.

## Resource exhaustion

- **Size.** multer `limits.fileSize` = 32 MB is enforced while streaming, so
  a larger body is a 413 before a buffer is materialised; `files: 1` refuses a
  second file part. Tested at 40 MB. Memory storage means up to 32 MB per
  concurrent upload in the API process — bounded by the one-in-flight rule per
  campaign, not globally. Accepted for the MVP: only hosts can upload.
- **Storage.** One in-flight source per campaign (partial unique index) caps
  how fast a host can fill `bytea`; finished sources accumulate until deleted.
  `ponytail:` in-row storage, move to object storage past ~50 MB (MVP.md D-1).

## Content type spoofing

The declared MIME and the filename are client-supplied. The `%PDF-` magic
bytes are checked first; the MIME is checked as well but never alone. A PDF
is still untrusted parser input: P4.1.2's `unpdf` read is where a malicious
PDF would bite, and that is outside this change. No bytes are executed,
rendered, or served back — `content` is never in any response.

## Data exposure

`content` is excluded by the projection (the columns selected), not by a
filter stripping it, so a forgotten field cannot leak it. Tested on every
status code of all four routes, including the 409 which embeds the in-flight
row. `filename` is stored as given (capped to 255) and is display text only —
never a filesystem path, so no traversal surface; the future UI renders it as
text. Copyrighted book text is never logged (NFR-503): no code here logs the
file or its name.

## Integrity and deletion

- Deleting a source nulls `campaign_notes.source_id` (FK `SET NULL`), so notes
  a host may have edited survive. Deleting a campaign cascades to its sources.
- `uploaded_by` is `SET NULL` on user deletion: a removed co-host's account
  does not take the campaign's book with it.
- The FK does not require a note's source to belong to the same campaign.
  P4.1.3 is the only writer of `source_id` and must set it from the source row
  it is processing; noted for that change.

## Untrusted content (invariant 7)

Stored bytes are data. The draft/publish human gate and the
`UNTRUSTED_BEGIN/END` wrapper are the controls for extracted text; both belong
to P4.1.3–P4.1.5 and are unchanged here.
