# M8.5 threat model — notes API and host editor

A new HTTP surface over `campaign_notes`, whose rows are `dm`-level content
(module spoilers) and whose bodies later reach the DM prompt (M8.3).

## 1. Disclosure — the primary risk

| Risk | Control |
|---|---|
| A player reads spoilers through `GET` | Reads are host-or-admin like writes: `CampaignMemberGuard` + `@CampaignRoles('host','admin')` on the **controller class**, so every route, including any added later, inherits it. Named test: a player's GET list and GET one are 403 and the body contains no note text. |
| Cross-campaign read/write | The guard checks membership of the route's `campaignId`; every query is `WHERE campaign_id = :campaignId AND slug = :slug`, so campaign B's slug through campaign A's route is 404. Asserted on GET, PATCH, DELETE and the list. |
| Probing campaign existence | The guard's existing identical 403 for non-member / wrong role / malformed id is unchanged. |
| Leaking whether a slug exists in another campaign | The 409 only fires within the caller's own campaign (the unique index is per campaign). |

## 2. Integrity

| Risk | Control |
|---|---|
| A host forging provenance (`sourceId`) to make a note look extracted | Not in either request schema; `.strict()` refuses it (400). Asserted. |
| Mass assignment of `campaignId`/`id` | `.strict()` schemas; `campaignId` comes from the guarded route param only. |
| Unique violation surfacing as 500 | Mapped to 409 `NOTE_SLUG_TAKEN` only for the named constraint; any other DB error still raises. |
| Stale routing context after a write (a deleted NPC still resolving, M8.4) | Every note write and every `progressionChapter` write calls `SessionContextService.invalidate`. Asserted. |
| Chapter write clobbering other settings | Merged into `settings.progression` with `||`; `null` removes only `chapter`. Asserted with a sibling key. |

## 3. Untrusted content

| Risk | Control |
|---|---|
| Note body carrying prompt injection into the DM turn | Not introduced here: bodies are host-authored and reach the prompt only through M8.3, inside the existing `UNTRUSTED_BEGIN/END` block (invariant 7). This change only stores them. |
| XSS in the editor | React renders titles/bodies as text; the body is a `<textarea>` value; no Markdown is rendered. |
| Oversized payloads | Body ≤ 100 000 chars, title ≤ 200, chapter ≤ 10 000; Nest's JSON body limit caps the request. `frontmatter` is an unvalidated object bounded by the same limit. |

## Residual

- `frontmatter` accepts any JSON object from a host. It is host-trusted
  campaign data; M8.3 decides what of it reaches the prompt.
- No rate limit specific to these routes, as for every other host write.
